Throughout the development of the **Due Dates + Overdue Filter** and **Tags / Labels** features for the Task Tracker, I primarily relied on the **Cursor Agent** integrated directly into the IDE. I used Cursor Agent for three key workflow phases: initial architecture planning, multi-file boilerplate generation, and writing Jest test suites for both backend end points and frontend components.

### A Moment AI Significantly Helped
Cursor Agent shone brightest when implementing the full-stack wiring for the **Tags / Labels** feature across multiple files simultaneously. By referencing `@TaskModal.jsx`, `@taskController.js`, and `@taskModel.js` in a single prompt, Cursor Agent added tag sanitization logic to the backend model, added query parameters to the controller, and built the interactive chip-input component in React in one agentic loop. Having the agent edit dependent files across the frontend and backend in parallel saved significant context-switching time and eliminated manual boilerplate wire-up.

### A Moment AI Slowed Me Down
AI slowed down progress when designing the **Overdue calculation strategy**. When prompted to handle task deadlines, Cursor Agent hallucinated an overly complex architectural design: it generated code to store an `is_overdue` boolean in the database, complete with a scheduled cron job worker intended to run every night at midnight to update task statuses. Testing this revealed synchronization bugs where tasks weren't updating in real time during timezone shifts. I spent nearly 30 minutes debugging and backing out of these unnecessary database schema additions and background scripts before directing the agent toward a simpler, dynamic computation model.

### A Moment My Review Changed the Result
Manual review was crucial when inspecting the AI-generated frontend UI and input validation for the task modal. Cursor Agent added an aggressive validation rule on the backend that rejected any incoming `due_date` set in the past, throwing a `422 Unprocessable Entity` error on creation. During manual verification, I realized this broke an important user workflow: team members frequently log completed tasks after the fact or backdate work that was already finished. Upon reviewing the output, I removed the strict past-date validation rule from the request body parser and modified the UI to allow historical dates while keeping the visual "Overdue" indicator intact for non-completed items.
